# Kaizen Platform

Внутренняя платформа для сбора и контроля кайдзен-предложений сотрудников компании.

## Как это устроено

- **Структура компании — дерево произвольной глубины**: отделы (Покраска, Сварка, Общая сборка, Логистика — как
  пример), а внутри каждого отдела — сколько угодно вложенных пунктов (Мастер → Бригадир → Оператор → Стажёр →
  ...; можно добавить подпункт у любого пункта, на любую глубину). У кого есть право «Структура компании», тот может
  добавлять/переименовывать/удалять отделы и пункты в любой момент.
- **Регистрация с подтверждением по иерархии**: при регистрации сотрудник выбирает отдел и пункт (должность). Заявка
  автоматически становится видна тому, кто занимает пункт на один уровень выше в том же отделе (например, заявку
  «Оператора» видит тот, кто стоит на пункте «Бригадир», а не любой бригадир вообще — именно родительский узел
  дерева). Для самого верхнего пункта отдела заявку видит только супер-админ или тот, кому выдано право
  «Подтверждать любые заявки».
- **Супер-администратор и гранулярные права**: есть один встроенный супер-админ (создаётся при `npm run seed`) —
  у него есть вообще всё, и только он может назначать других супер-админов или выдавать право «Назначение прав».
  Помимо этого, любому подтверждённому сотруднику можно выдать по отдельности любой набор прав: «Структура
  компании», «Пользователи», «Назначение прав», «Подтверждать любые заявки», «Все кайдзен-предложения» — а также
  задать произвольное название роли (например, «Модератор кайдзенов»), которое будет показываться вместо
  обычного бейджа «admin». Всё это настраивается в разделе «Пользователи» → «Права...» у каждого сотрудника.
- **Пароли** хранятся только в виде bcrypt-хэшей, вход — по логину/паролю с выдачей JWT-токена.
- **Кайдзен-предложения**: любой подтверждённый сотрудник может подать предложение (название, описание, необязательная
  категория). Те, у кого есть право «Все кайдзен-предложения» (или супер-админ), видят все предложения и управляют
  статусом: `Новое → На рассмотрении → Принято/Отклонено → Внедрено`, с комментарием и историей изменений статуса.

## Структура проекта

```
kaizen-platform/
  server/   — backend: Node.js + Express + SQLite (встроенный модуль node:sqlite)
  client/   — frontend: React + Vite
```

## Запуск (локально)

Требуется **Node.js 22.5+** (нужен для встроенного `node:sqlite`; специально выбран, чтобы не требовалась
компиляция нативных модулей — значит, не нужны ни Visual Studio Build Tools на Windows, ни Xcode Command Line
Tools на macOS). Проверить версию: `node -v`.

При запуске backend в консоли может появиться жёлтое предупреждение
`ExperimentalWarning: SQLite is an experimental feature` — это нормально, не ошибка, работе не мешает.

### Проблемы при установке на Windows

- **`npm : File ... cannot be loaded because running scripts is disabled`** (PowerShell) — выполните один раз:
  `Set-ExecutionPolicy -Scope CurrentUser -ExecutionPolicy RemoteSigned`, подтвердите `Y`.
- **`&&` не работает в PowerShell** — выполняйте команды по одной, на отдельных строках (это не bash/cmd).

### 1. Backend

```bash
cd server
npm install
npm run seed   # создаёт администратора и пример структуры отделов (один раз)
npm start       # запускает API на http://localhost:4000
```

По умолчанию создаётся супер-администратор:
- логин: `admin`
- пароль: `admin12345`

**Обязательно смените этот пароль после первого входа** (в разделе «Пользователи» → «Сбросить пароль», либо задайте
свои значения через переменные окружения `SEED_ADMIN_LOGIN` / `SEED_ADMIN_PASSWORD` перед запуском `npm run seed`).

Если вы уже запускали более раннюю версию этой платформы (со старой структурой должностей и полем `is_admin`), просто
установите новую версию поверх и запустите `npm start` как обычно — при первом старте существующая база данных
автоматически, без потери данных, переносится на новую схему (старый администратор становится супер-администратором,
линейный список должностей превращается в дерево с теми же связями).

Переменные окружения (необязательно, можно создать `server/.env`):
```
PORT=4000
JWT_SECRET=замените-на-длинную-случайную-строку
SEED_ADMIN_LOGIN=admin
SEED_ADMIN_PASSWORD=admin12345
```

### 2. Frontend

В отдельном терминале:

```bash
cd client
npm install
npm run dev    # запускает интерфейс на http://localhost:5173
```

Frontend в режиме разработки автоматически проксирует запросы `/api/*` на backend (см. `client/vite.config.js`).
Откройте http://localhost:5173 в браузере.

### Сборка для продакшена

```bash
cd client
npm run build   # соберёт статику в client/dist
```

Полученную папку `client/dist` можно раздавать любым веб-сервером (nginx, Caddy и т.п.), настроив проксирование
`/api/*` на backend-процесс (`server`, порт 4000). Backend можно держать в работе через `pm2`, `systemd` или
Docker-контейнер — в текущей поставке это не настроено и потребует отдельной инфраструктурной работы.

## Как настроить структуру и права под вашу компанию

1. Зайдите супер-админом → «Структура компании».
2. Создайте отделы (например, ваши реальные подразделения завода).
3. В каждом отделе стройте дерево: добавьте пункт верхнего уровня (например «Мастер»), затем у него — подпункт
   («Бригадир»), затем у «Бригадира» — свой подпункт («Оператор»), и так далее на любую глубину. Переименовать или
   удалить пункт можно в любой момент; удаление удаляет и все вложенные подпункты.
4. Когда сотрудник регистрируется, он выбирает отдел и пункт. Заявка появится во вкладке «Заявки на подтверждение»
   у того, кто занимает пункт ровно на уровень выше (родительский узел), либо у супер-админа/обладателя права
   «Подтверждать любые заявки» — для самого верхнего пункта отдела.
5. Чтобы делегировать часть административных функций: «Пользователи» → у нужного сотрудника нажмите «Права...» →
   отметьте нужные права по отдельности и, при желании, впишите название роли. Права «Назначение прав» и статус
   супер-администратора может выдавать только сам супер-администратор — это защита от случайной передачи полного
   контроля.

## Что уже есть в MVP

- Регистрация/вход, хэширование паролей, JWT.
- Структура компании в виде дерева произвольной вложенности (отдел → пункт → подпункт → ... ), полностью
  управляемая через интерфейс.
- Иерархическое подтверждение регистрации по дереву, с проверкой на бэкенде (не только в интерфейсе).
- Супер-администратор + гранулярные права, назначаемые по отдельности любому сотруднику, с произвольным названием
  роли.
- Подача кайдзен-предложений, просмотр своих предложений, статусы и история изменений.
- Раздел «Пользователи»: подтверждение/отклонение заявок, смена отдела-пункта, права доступа, блокировка, сброс
  пароля, удаление. Раздел «Все предложения»: просмотр всех кайдзенов и управление статусом — виден тем, у кого
  есть соответствующее право.

## Что можно добавить дальше (не реализовано в этой версии)

- Вложения к предложениям (фото/файлы).
- Уведомления (email/Telegram) о новых заявках и изменениях статуса.
- Оценка экономического эффекта и рейтинг лучших предложений/сотрудников.
- Ролевой доступ «руководитель отдела видит все кайдзены своего отдела» (сейчас это может администратор; можно
  расширить эндпоинт `/api/kaizens?scope=department`, который уже частично реализован на бэкенде).
- Экспорт отчётов (Excel/PDF).
- Полноценное развёртывание (Docker, HTTPS, резервное копирование SQLite-базы `server/data/kaizen.db`).
