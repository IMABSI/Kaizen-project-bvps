# Kaizen · Платформа предложений по улучшению

Платформа, где сотрудники завода подают кайдзен-предложения (идеи постоянного улучшения).
Интерфейс на трёх языках (русский, узбекский латиницей, английский), светлая и тёмная темы, работает на телефоне.

## Как устроены люди и доступ

- **Аккаунты есть только у мастеров и выше.** Вход — по **табельному номеру** (целое число 1–3000) и паролю.
- **Операторы и бригадиры без аккаунтов.** Мастер сам строит свою структуру в разделе «Моя команда»
  (дерево любой глубины, любые должности). Каждому достаточно табельного номера.
- **Табельный номер уникален по всей компании** — и среди аккаунтов, и среди сотрудников команд.
- **Первый вход через одноразовый код.** Администратор создаёт мастера (табельный №, ФИО, отдел) и получает
  код вида `ABCD-2345`. Код показывается один раз, действует 7 дней, после 5 неверных попыток сгорает.
  Сотрудник вводит табельный номер + код и сам задаёт пароль. Так никто не может «занять» чужой аккаунт,
  просто угадав табельный номер. Забыл пароль — администратор выдаёт новый код (старый пароль и сессии сбрасываются).
- **Права** выдаются точечно (структура, пользователи, права, кайдзены, просмотр), есть защита от повышения
  привилегий и от удаления/отключения последнего супер-администратора.
- Часовой пояс отображения — GMT+5 (Ташкент). Язык и тема запоминаются в профиле.

## Карточка кайдзена

- Поля: название, категория (Cost / Quality / Safety & 5S / Efficiency / Other), участок, оборудование, дата обнаружения,
  тип потерь и ожидаемый эффект (выбор из списков), блоки «проблема / до / после / выгоды» и «вывод» — у каждого до 4 фото с подписью,
  замеры «до / после» (процент изменения считается сам), стадия внедрения, затраты, экономия, трудоёмкость, участники.
- Мастер подаёт кайдзен от своего имени или от имени сотрудника своей команды. Данные автора идеи, мастера и отдела
  копируются в карточку и не меняются, если потом поменяется структура.
- Номер карты сквозной и не повторяется, удалённые карточки только скрываются.
- Статусы: отправлен / принят / отклонён (ставит администратор). Автор правит сутки; дальше — по разрешению администратора.
- Видимость: по умолчанию все вошедшие видят все кайдзены; супер-администратор может включить режим `restricted`
  (свои, отдел и те, у кого есть право просмотра).
- Печать A4 — кнопка «Печать A4» в карточке; на фоне диагонально табельный номер автора идеи.
- Фото хранятся в `server/data/uploads` (или `UPLOAD_DIR`) и отдаются только по токену. **При резервном копировании сохраняйте и базу, и эту папку.**
  Фото с телефона сжимаются в браузере до 1600 px, лимит — 5 МБ.

## Запуск (разработка)

Нужен **Node.js 22.5 или новее** (используется встроенный SQLite). Проверка: `node -v`.

```bash
# 1. сервер
cd server
npm install
npm run seed    # супер-администратор + отдел «Логистика»
npm start       # API на http://localhost:4000

# 2. клиент (другой терминал)
cd client
npm install
npm run dev     # http://localhost:5173
```

Первый вход: табельный номер `1`, пароль `admin12345` (значения меняются переменными
`SEED_ADMIN_TABEL`, `SEED_ADMIN_PASSWORD`, `SEED_ADMIN_NAME` перед `npm run seed`). **Сразу смените пароль** в «Профиле».

В консоли сервера может быть предупреждение `ExperimentalWarning: SQLite is an experimental feature` — это нормально.

### Windows
- `npm : ... running scripts is disabled` (PowerShell) — один раз: `Set-ExecutionPolicy -Scope CurrentUser -ExecutionPolicy RemoteSigned`.
- `&&` в PowerShell не работает — запускайте команды по одной.

### База данных
Файл `server/data/kaizen.db`. Схема обновляется автоматически (версионные миграции).
Если найдена база старой структуры (до этого этапа) — она копируется в `kaizen.db.legacy-<время>.bak`
и создаётся заново (реальных данных в ней не было).

## Тесты

```bash
cd server && npm test     # API: вход, активация, права, команды, миграции, seed, кайдзены (на временной БД в памяти)
cd client && npm test     # интерфейс: словари, переводы ошибок, дерево команды, даты, вход/активация/роли
cd client && npm run lint && npm run build
```

Тест словарей проверяет, что в ru/uz/en одинаковые ключи и что для каждого кода ошибки сервера есть перевод.

## Продакшен
Клиент: `npm run build` → папка `client/dist` раздаётся веб-сервером, `/api/*` проксируется на `server` (порт 4000).
Обязательно: `NODE_ENV=production`, длинный `JWT_SECRET`, HTTPS, при прокси — `TRUST_PROXY=1`.
См. `server/.env.example`.
