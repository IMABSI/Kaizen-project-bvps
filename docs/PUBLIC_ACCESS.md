# Как открыть сайт для сотрудников (туннель с вашего компьютера)

Это временный вариант для пробы. Сайт работает, пока **компьютер включён, не спит и есть интернет**.
Когда будете готовы — тот же проект переносится на сервер компании без изменений кода (шаги 1–3 те же, вместо туннеля — адрес сервера).

> Перед открытием сайта наружу согласуйте это с ИТ/старшими: на сайте будут данные завода.

## 0. Один раз: настройки

1. В папке `server` создайте файл `.env` (скопируйте `.env.example`) и заполните:
   ```
   NODE_ENV=production
   PORT=4000
   JWT_SECRET=<длинная случайная строка>
   TRUST_PROXY=1
   SEED_ADMIN_TABEL=<ваш табельный номер>
   SEED_ADMIN_PASSWORD=<ваш надёжный пароль>
   ```
   Случайную строку для `JWT_SECRET` получите командой:
   `node -e "console.log(require('crypto').randomBytes(48).toString('hex'))"`
2. `TRUST_PROXY=1` **обязателен**: без него защита от подбора пароля решит, что все сотрудники приходят с одного адреса,
   и несколько ошибок входа у кого-то одного заблокируют вход всем.
3. Если база уже создана раньше, пароль админа не изменится при повторном `npm run seed`. Смените его в «Профиле».

## 1. Собрать сайт и запустить сервер

```
cd client
npm install
npm run build

cd ../server
npm install
npm run seed
npm start
```
Проверьте на самом компьютере: откройте http://localhost:4000 — должна открыться страница входа (сайт и API теперь на одном порту).

## 2. Открыть наружу через Cloudflare Tunnel (бесплатно)

1. Установите программу (PowerShell): `winget install --id Cloudflare.cloudflared`, затем закройте и откройте терминал.
2. В **новом** окне терминала: `cloudflared tunnel --url http://localhost:4000`
3. В выводе появится адрес вида `https://что-то-случайное.trycloudflare.com` — это и есть адрес сайта, он уже с HTTPS.
   Отправьте его сотрудникам.

Ограничения этого способа:
- адрес **меняется при каждом запуске** туннеля;
- Cloudflare не гарантирует работу такого «быстрого» туннеля (он для проб);
- постоянный адрес возможен с бесплатным аккаунтом Cloudflare и своим доменом (около 10 долларов в год) — скажите, настрою инструкцию.

## 3. Чтобы компьютер не мешал

- Параметры → Система → Питание: «Спящий режим — никогда» на время работы сайта.
- Окна с `npm start` и `cloudflared` должны оставаться открытыми.

## Резервные копии (делайте регулярно!)

```
cd server
npm run backup
```
Копия (база + фото) сохраняется в `server/backups/<дата-время>`, хранятся последние 14.
Чтобы делать это автоматически: «Планировщик заданий» Windows → создать задачу раз в день → программа `npm`, аргументы `run backup`, папка `...\server`.
Хотя бы раз в неделю копируйте папку `server/backups` на флешку или в облако.

## Обновление сайта новой версией

```
git checkout main
git pull
cd client && npm install && npm run build
cd ../server && npm install
```
Затем перезапустите `npm start` (в окне сервера `Ctrl+C`, потом `npm start`). Туннель перезапускать не нужно.
Перед обновлением сделайте `npm run backup`.

## Если что-то не работает

| Симптом | Что проверить |
|---|---|
| Сервер не стартует: «JWT_SECRET» | нет `JWT_SECRET` в `.env` при `NODE_ENV=production` |
| По адресу туннеля «502 / Bad gateway» | сервер `npm start` не запущен или порт не 4000 |
| Не удаётся войти всем сразу после нескольких ошибок | не задан `TRUST_PROXY=1` |
| Страница открывается, но «нет связи с сервером» | перезапустите сервер, проверьте `http://localhost:4000/api/health` |
